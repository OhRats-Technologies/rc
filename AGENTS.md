# RC

Remote device control plane for OhRats Technologies.

## Rules

- Keep the control plane small and observable.
- Treat disconnects, stale devices, and interrupted processes as normal states.
- Never store Node private keys or plaintext auth/enrollment tokens server-side.
- Passkeys are the human credential; there is no email/password or recovery flow. Human CLI login uses the passkey-backed browser authorization flow.
- Public account signup is an explicit deployment policy, disabled by default. When enabled, require a configured Cloudflare Turnstile Managed widget and successful server-side Siteverify validation before issuing the signup WebAuthn ceremony. Never replace protected first-instance setup with public signup, and do not add a second CAPTCHA/rate-limit system inside RC when Cloudflare is the managed-service abuse boundary.
- API keys are automation proof-of-possession credentials only. Generate their Ed25519 private keys client-side, store only public keys/scopes server-side, and sign each request including method, path/query, timestamp, nonce, and body SHA-256. Never reintroduce bearer API tokens. Keep key management visible under the API route and do not offer API keys as browser-login substitutes. Key administration itself requires a human browser session.
- Remote MCP lives at `/mcp` and is a thin adapter over RC domains, not a parallel control plane. Keep the focused process harness—`machines_list`, `process_run`, `process_status`, `process_input`, `process_cancel`—plus the narrow `image_view` visual primitive instead of adding overlapping shell/session/general-filesystem operations. Observe is read-only; Terminal is explicit. `process_run` starts a non-PTY process, `process_status` is the sole output reader, `process_input` writes exact bytes/EOF without an implicit newline, and `process_cancel` requests INT/TERM/KILL. Execution-capable grants require a fresh passkey ceremony, explicit device selection, current Owner authority, a maximum ~30-day lifetime, and inclusion in RC Lock before the Node will execute them. Do not add ambient “all future devices” execution authority without a separately reviewed, versioned RC Lock protocol change. OAuth access tokens are short-lived and resource-bound; refresh tokens rotate. Every tool that returns `structuredContent` must publish an exact `outputSchema`. Do not expose device update/removal through MCP v1.
- Exact argv, portable RC Shell source, native system-shell commands, and native interactive login shells are distinct execution modes. Never quote exact argv into shell source, and never make portable RC Shell an alias for `/bin/sh`, PowerShell, or `cmd.exe`. Browser/CLI interactive execution uses an attached lease with bounded reattach grace; MCP uses a managed lease; scheduler runs use scheduled leases. The Node owns execution IDs, trees, authorization linkage, and bounded output journals across controller/server disconnects.
- Do not put arbitrary `minLength`/`maxLength` constraints on MCP strings. Reject semantic emptiness where relevant and enforce capacity at the owning boundary: HTTP request body, serialized Node control frame, decoded stdin chunk, or rolling output buffer. MCP process output is ordered labeled chunks addressed by an absolute cursor; coalesce adjacent chunks from the same stream in tool responses without changing cursor accounting or merging across stdout/stderr boundaries. Never freeze on the first full buffer or silently evict a live process. Command, input, and output plaintext transit hosted RC memory only and must never be persisted or logged.
- Shared visual primitives use content-fingerprinted immutable URLs under `https://assets.ohrats.party/assets/`.
- Follow cross-product UI guidance in `../handbook/design/ui.md`; when review feedback generalizes, promote it there/shared UI instead of keeping a one-off local fix.
- Product CSS must use existing `--or-*` tokens; do not invent a parallel design system.
- Keep browser source typed. Bun may remain as the private build tool of the WebUI component, but it must not participate in kernel or unrelated component builds. Do not add an untyped `public/js` tree.
- API routes are versioned under `/api/v1`.
- Persist server state under `/data` in production.
- Keep every maintained source file under 300 lines. Split by responsibility before a file reaches that size.
- WIT owns cross-component contracts. Components may be implemented in any language that produces a valid WebAssembly Component. Keep deterministic fixtures for wire and cryptographic contracts rather than coupling those contracts to one implementation language.
- Global navigation uses the persistent sidebar. Keep brand/collapse chrome pinned while the navigation tree scrolls. Workspace folders disclose device children; the folder click itself does not navigate. Disclosure height animates rather than snapping. Keep child lists bounded. Workspace and device rows share one composite row/context-menu treatment; device depth comes from inline-start indentation. Keep workspace enrollment/access/audit plus rename/delete lifecycle actions in the workspace ellipsis, and device rename/update/delete in the device ellipsis. Edit simple names directly in their labels and dismiss menus on outside interaction/Escape. Do not add workspace overview/detail pages that only duplicate sidebar functionality.
- Workspace creation is inline in the sidebar folder list. Enter creates; Escape/blur cancels. Do not reintroduce `/workspaces` or `/workspaces/new` HTML pages unless they gain materially distinct product functionality.
- Device presence is always visible in the hierarchy and uses shared semantic positive/negative state tokens. Long child labels may marquee only while hovered/focused and only when measured overflow exists; keep the row itself still and respect reduced motion.
- Device/workspace deletion is confirmed in the shared semantic sidebar dialog and then uses the authenticated DELETE API. Do not reintroduce dedicated delete-confirmation pages for these lightweight lifecycle actions.
- Keep the device page operationally minimal: platform + identity/presence, host + Node version, compact header rename/terminal/delete actions, and active processes. Show completed lifecycle history only when the deployment explicitly enables metadata retention. Do not duplicate RC/server and Node versions when they are normally equal; surface version mismatch through the contextual update action. Do not reintroduce the custom command/cwd form in the device UI; explicit commands belong to API, CLI, or MCP Terminal.
- Execution history is disabled by default. Persist a process row only while it is required for live authorization, ownership, at-most-once execution, and reconnect reconciliation; after the live completion/loss event, remove it unless `RC_EXECUTION_HISTORY=metadata`. Metadata mode may retain only process ID, device, origin, PTY flag, state, attribution, timestamps, exit code/signal, and bounded error text for the configured TTL. Never persist command, cwd, terminal geometry, stdin/stdout/stderr, transcript revisions, or transport-session diagnostics. Live browser/CLI terminal scrollback is a bounded RC Node in-memory buffer replayed on authorized reattach and disappears when the process or Node ends.
- Standalone collection pages use compact header creation controls rather than permanent creation sections when the task is short. API key creation is a header-plus modal with a normal `/api/keys/new` form fallback; the one-time key is revealed immediately with the shared copy control.
- A detail-page header may repeat the immediate identity/lifecycle actions that are useful while already viewing that object (for example device rename/delete) even when the persistent sidebar also exposes them contextually. Keep the action set compact and reuse the same underlying operation/dialog rather than creating a second workflow. Account deletion uses the shared centered delete dialog. Native dialogs must remain explicitly centered despite the shared universal margin reset.
- Account display-name edits happen directly in the page title. Account deletion removes the account, deletes every workspace where that account is an Owner, leaves non-owned workspaces through membership cascade, preserves surviving historical attribution as `Deleted account`, and returns to protected setup when no human accounts remain.
- Top-level collection pages use one page title (`Devices`, `API`, `MCP`) without repeating the same noun as an eyebrow. Detail/workflow pages may use an eyebrow when it contributes object/context information such as `DEVICE` or `WORKSPACE / ACCESS`.
- Device-list platform marks are based on operating-system platform, not CPU architecture. Keep macOS/Linux/Windows marks on the same normalized monochrome canvas and let shared CSS color them through `currentColor`; architecture remains textual metadata.
- Authenticated routes are ordinary server-rendered URLs. Do not require client-side routing for navigation. JavaScript may enhance individual pages but must not own primary page rendering.
- Prefer normal links, forms, POST/redirect flows, and server-rendered snapshots. JavaScript is reserved for capabilities that inherently require it or materially benefit from live enhancement.
- Keep authenticated pages visually flat: natural sections, typography, rows, and dividers. Do not turn every section into a bordered panel/card.
- Browser/CLI control-session setup and non-trickle WebRTC signaling use authenticated HTTP endpoints. Browser live metadata/events use cookie-authenticated Server-Sent Events (SSE). Browser/CLI interactive control uses only a WebRTC DataChannel after the Node-authorized control handshake; ICE may choose direct or TURN relay candidates. There is no browser/human-CLI WebSocket endpoint. Do not reintroduce timer polling or make hosted RC the browser/CLI data plane.
- WebRTC control frames are JSON text DataChannel messages in both directions. The browser may accept binary JSON only as rolling-upgrade compatibility; Nodes should use text frames so browser transport code does not misclassify a valid direct frame as invalid and fall back to relay.
- Browser terminals use xterm.js WebGL2 rendering (`@xterm/addon-webgl`) when available for canvas/GPU rendering, and gracefully fall back to xterm's default renderer if WebGL initialization or context retention fails.
- The device and human CLI share the `rc` binary. Keep the product name `RC`; OhRats is established by the product domain and company mark rather than repeated in the product name.
- Normal install/enrollment starts the Node as a per-user background service. `rc run` is the foreground/debug path, not a required second terminal in the normal setup flow.
- Device removal is available from the web, `DELETE /api/v1/devices/:id`, and `rc device delete`. Deletion commits on RC immediately and creates the revocation tombstone used for signed Node reconciliation; do not add a parallel encrypted `node.remove` command.
- Keep the product model `User → Workspace → Device → Process`. Do not add fleets or browser shell-session wrappers without a concrete need.
- Remote processes are byte-stream processes with an optional terminal attachment. `rc shell` and the browser terminal request a PTY; non-interactive execution such as `rc run` uses separate binary-safe stdin/stdout/stderr streams. Keep this primitive generic so SSH/SFTP/rsync can build on it without filesystem-specific Node RPCs.
- SSH compatibility uses stock OpenSSH `sshd` in the RC gateway container, not a JavaScript SSH implementation and not an SSH daemon on Nodes. Password/keyboard auth and forwarding are disabled. `AuthorizedKeysCommand` maps registered public keys to a forced RC bridge; generated OpenSSH config sends the full immutable RC device ID and uses `rc ssh-proxy` over the public WebSocket endpoint so client networks do not need outbound SSH ports. Keep device names out of routing authority.
- Device deletion is server-authoritative and must work while a Node is offline. Persist a minimal revoked-device tombstone before deleting the visible device row. A previously enrolled Node signs its normal HTTP proof-of-possession request against that tombstone, receives HTTP 410 on reconnect, then clears its local enrollment and background service. Keep generic unknown-device 404 behavior distinct so server/database mistakes do not cause locked Nodes to self-delete.
- `rc update` changes managed Wasm components and does not replace the native kernel. `rc upgrade` changes the kernel. An update that resolves to the installed component digest must not replace, reactivate, or restart that component.
- Only one RC Node process may own a local enrollment at a time. `rc run` and the background service share a non-blocking per-state-directory file lock; a second process must fail locally instead of opening a competing signed HTTP/WebRTC Node transport and causing replacement churn.
- Browser live process/device state comes from cookie-authenticated SSE at `/api/v1/events`. Do not poll process snapshots for ordinary `process.started`, `process.exited`, `process.lost`, `device.online`, or `device.offline` events; HTTP snapshots are for initial load or explicit SSE reconnect/gap recovery.
- On every Node connect/reconnect, `process.sync` is authoritative for the active local process IDs. Any hosted `starting`/`running` row for that device that is absent from the sync must transition to `lost`; reconnect must never leave a hosted process permanently `running` when the Node no longer owns it.
- Remote processes are at-most-once. If execution becomes ambiguous after disconnect/restart, mark it lost instead of replaying it. RC Node shutdown, crash, and update must tear down every remote process tree; never leave detached remote work behind.
- Durable schedules are Node-local first-party component state. Hosted RC stores only signed RC Lock permit metadata/spec hashes; human CLI schedule definitions travel over encrypted WebRTC control. Every trigger enters the ordinary execution runtime, defaults to no overlap, and loses future/active authority when its permit is revoked. Do not translate schedules into OS cron/launchd/Task Scheduler jobs.
- RC Node authentication uses replay-resistant Ed25519-signed HTTP requests that bind method, path/query, timestamp, nonce, and body. Never put reusable signatures or authentication secrets in URLs.
- Native kernel releases and portable component releases are independent. Remote artifacts are staged outside the trusted component directory and pinned by digest before atomic placement. Local files deliberately placed in the trusted component directory are trusted by placement. The kernel may expose one atomic replace/re-exec primitive but must not own package-update policy.
- RC Lock is enforced locally by the Node. Its persisted authority snapshot owns member roles, passkey credential public keys, API signing public keys/scopes, and active execution-capable MCP grant hashes. First initialization is TOFU from the currently trusted instance and may never overwrite an existing lock. Every later snapshot must be signed by an existing Owner using a passkey-authorized control key; server database state alone is not authority. Accepting a new snapshot invalidates every live encrypted control session so removed/demoted identities must reopen against the new Node-local authority.
- Human browser/CLI control grants default to 30 days, but each live browser/CLI control connection uses fresh X25519 client and Node ephemeral keys. Mix those with the Node's pinned static X25519 key via HKDF-SHA256 and encrypt control frames with AES-256-GCM. The Node's Ed25519 identity signs the live handshake. Browser/CLI control is WebRTC DataChannel-only; do not add a WSS/hosted relay fallback or send process commands, streams, signals, or node updates outside this encrypted Node-verified channel. MCP Terminal and gateway-terminated SSH are deliberate transport exceptions: their command/output plaintext transits RC memory and must never be persisted. Nodes still independently verify the supplied passkey-backed execution authority before starting a process.
- The native kernel owns Wasmtime, WIT linking, component discovery, dependency reconciliation, effect ownership, resource limits, operating-system adapters, CLI dispatch, recovery, and kernel re-exec. It must not acquire RC product-domain types or policy.
- Official and third-party product behavior is implemented as Wasm components. Each component has its own manifest, lockfile, build, version, artifact, and declared WIT imports/exports even when it lives in this monorepo. Never load Rust dynamic libraries as the component ABI.
- An implementation-only kernel change builds only native kernel targets. An implementation-only component change builds only that component. A WIT change rebuilds the components that import it. A profile/lock change assembles artifacts without compiling code.
- Components receive no ambient filesystem, network, process, key, or environment access. The host links only the interfaces granted to that component. Trusted placement authorizes execution; WIT imports still enforce least privilege and fault containment between installed components.
- Diagnostics are structured, bounded metadata only. Diagnostic WIT must not expose command text, cwd, stdin/stdout/stderr, terminal transcripts, credentials, private keys, passkeys, or tokens. Cross-node diagnostics require an explicit authority service; mesh reachability alone is never permission to inspect another Node.
- Components register CLI commands, HTTP routes, transports, crypto algorithms, diagnostics, UI slots, and package sources as typed services. Registration is lease/effect owned: withdrawal removes the service and deactivates dependents. A failed replacement must leave the previous healthy generation active.
- The native HTTP adapter owns sockets, body/header limits, request conversion, health, and generic 404/500 handling only. Product routes, HTML, sessions, WebAuthn flows, APIs, and assets belong to components. Component-owned public assets use content-fingerprinted immutable URLs; dynamic/authenticated responses use `no-store` or revalidation as appropriate.
- Peer capability announcements are signed, expiring descriptions of behavior, never authority. Negotiate version and feature intersections, then let local policy select a compatible provider. The destination still verifies RC Lock and the operation permit.
- Mesh transport providers carry only opaque encrypted control frames; they never acquire execution authority. `rc.ohrats.party` is Tier-0 and may never accept another coordinator as upstream authority.
- `ROADMAP.md` is the migration specification and live checklist. Complete, validate, and check off tasks in the same change. Delete replaced monolith code instead of maintaining parallel implementations or compatibility scaffolding.
- `loom join`; coordination path/state/lang/runtime resolved by Loom. RC path/schema/import knowledge∅. worker id unique + isolated worktree; thread/dm/vote public; exact literals exact; secrets∅.
- Cloudflare TURN long-lived credentials (`RC_CF_TURN_TOKEN_ID`, `RC_CF_TURN_API_TOKEN`) are backend-only. RC may mint/cache short-lived ICE credentials and pass only those temporary values to browser/Node. Never persist or expose the long-lived TURN secrets. Browser/CLI encrypted control frames are WebRTC DataChannel-only; ICE may select direct or TURN relay candidates. HTTP/SSE carry metadata and signaling only and must never carry control ciphertext frames.
- A locked Node must preserve local enrollment and RC Lock state for generic unknown-device 404s. Only an authenticated revocation response backed by the Node's persisted tombstone (410 Gone) or explicit local uninstall may erase locked state.
